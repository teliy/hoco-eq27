# EQ27 ANC — своё приложение-управлялка для HOCO EQ27

[![CI](https://github.com/teliy/hoco-eq27/actions/workflows/ci.yml/badge.svg)](https://github.com/teliy/hoco-eq27/actions/workflows/ci.yml)
[![Release](https://github.com/teliy/hoco-eq27/actions/workflows/release.yml/badge.svg)](https://github.com/teliy/hoco-eq27/releases)

Репозиторий: **https://github.com/teliy/hoco-eq27**

Нативное Android-приложение (Kotlin + Jetpack Compose), которое подключается к наушникам
**HOCO EQ27** по Bluetooth LE и позволяет **управлять шумоподавлением (ANC)**: вкл / выкл /
прозрачный режим — без фирменного приложения hoco.music.

Проект спроектирован с учётом того, что протокол управления EQ27 — вендорский (наушники
построены на чипе **JieLi AC7003D4**, приложение hoco.music собрано на фирменном стеке
**RCSP** от Jieli). Точную ANC-команду нужно один раз «поймать» из hoco.music — в проект
уже встроены все инструменты для этого (см. раздел **«Поймать команду ANC»**).

## Как это работает

```
+----------------+        BLE (GATT)         +-----------------+
|  EQ27 ANC      |  TX: write-характеристика  |   HOCO EQ27     |
|  (это app)     |  RX: notify-характеристика |  (JL AC7003D4)  |
+----------------+                            +-----------------+
        |                                              |
        |  1. Скан → фильтр по имени «EQ27»            |
        |  2. connectGatt (TRANSPORT_LE)               |
        |  3. discoverServices → MTU 247               |
        |  4. Автовыбор TX/RX (сервисы Jieli 0xAE00/…) |
        |  5. Пишем кадры ANC → наушники переключают   |
        |     режим шумоподавления                     |
```

Классический аудиоканал (A2DP для музыки) остаётся системным — приложение работает
с наушниками **параллельно** с обычным воспроизведением, сопряжение не трогаем.

## Требования

- **Android Studio** — Hedgehog 2023.1.1 или новее (подойдёт любая свежая версия)
- **JDK 17** — идёт в комплекте с современными версиями Android Studio
- Телефон с **Android 12+** (API 31) и Bluetooth LE — minSdk проекта = 31
- Сами наушники HOCO EQ27 и приложение **hoco.music** (для перехвата команд, один раз)

## Сборка проекта

1. Распакуйте архив проекта.
2. Android Studio → **File → Open** → выберите папку `EQ27-ANC`.
3. Дождитесь **Gradle Sync** (первый раз скачает Gradle 8.7 и зависимости — нужен интернет).
4. Сборка: **Build → Build Bundle(s)/APK(s) → Build APK(s)**.
5. Готовый APK: `app/build/outputs/apk/debug/app-debug.apk`.

Через консоль:

```bash
./gradlew assembleDebug        # Linux/macOS
gradlew.bat assembleDebug      # Windows
```

> Если Android Studio предложит обновить Gradle-плагин — можно отказаться,
> проект настроен на AGP 8.5.2 / Kotlin 2.0.20 / Gradle 8.7.

## Установка на телефон

- Вариант А: **Run ▶** в Android Studio при подключённом телефоне (включите «Отладка по USB»).
- Вариант Б: скопируйте `app-debug.apk` на телефон и откройте файл
  (разрешите «Установка из неизвестных источников»).

При первом запуске приложение попросит разрешения **BLUETOOTH_SCAN** и
**BLUETOOTH_CONNECT** — выдайте оба. Геолокация не используется
(в манифесте стоит флаг `neverForLocation`).

## Обновление из приложения

На вкладке **«Подключение»** внизу есть карточка **«Обновление приложения»**:

- **«Проверить обновления»** — приложение читает последний релиз репозитория через
  GitHub Releases API и сравнивает тег (`v1.2.3`) с установленной версией;
- **«Обновить версию»** — если релиз новее, APK скачивается во внутренний кэш
  (с прогрессом) и запускается системный установщик;
- при первом обновлении Android попросит разрешить установку из этого приложения
  (Настройки → «Установка неизвестных приложений») — разрешите и нажмите
  **«Установить»** ещё раз.

### Как выпустить новую версию

Подпись APK должна совпадать с установленной версией — поэтому ключ
`keystore/eq27-release.jks` лежит в репозитории и используется и локально,
и в GitHub Actions (пароль публичный намеренно: релизы под вашим контролем).

1. Поднимите версию в `app/build.gradle.kts`: `versionCode += 1`, `versionName = "1.1.0"`.
2. Закоммитьте и поставьте тег:

   ```bash
   git add .
   git commit -m "v1.1.0"
   git tag v1.1.0
   git push origin main --tags
   ```

3. Workflow **Release** соберёт подписанный APK и приложит его к релизу
   (`eq27-anc-1.1.0.apk`) автоматически.
4. Через несколько минут кнопка «Проверить обновления» на телефонах с версией 1.0.0
   предложит обновиться до 1.1.0.

> **Важно:** если соберёте APK локально другим ключом (своим debug-ключом Android Studio),
> обновление из релиза не установится — Android отвергает APK с другой подписью.
> Ключ из репозитория решает это автоматически.

## Первое подключение

1. Достаньте наушники из кейса, наденьте их.
2. **Закройте hoco.music** — два приложения могут конфликтовать за BLE-канал управления.
3. Вкладка **«Подключение»**: фильтр имени `EQ27` → «Начать поиск».
4. Нажмите на найденное устройство. Приложение подключится, запросит MTU 247,
   автоматически найдёт TX (write) и RX (notify) характеристики и включит уведомления.
5. Зелёный баннер сверху = соединение готово. Загляните в **«Лаборатория» → «Дамп GATT»** —
   увидите все сервисы/характеристики наушников (это пригодится для перехвата).

Если наушники не нашлись: включите «Показывать все BLE» — имя в advertising может
отличаться от имени в системных настройках (`HOCO EQ27`, `EQ27`, просто цифры и т.п.).

## Поймать команду ANC

Это ключевой раздел. Один раз поймав кадры из hoco.music, вы получаете полный
контроль из своего приложения.

### Шаг 1. Включите журнал HCI

Настройки → **Для разработчиков** → включите
**«Журнал отслеживания Bluetooth HCI»** (Enable Bluetooth HCI snoop log).

### Шаг 2. Снимите трафик hoco.music

1. **Выключите и включите Bluetooth** (лог пишется с момента включения стека).
2. Подключите наушники, откройте **hoco.music**.
3. Переключайте ANC **с паузами 5–7 секунд**, чтобы кадры легко различались во времени:
   - выключить ANC → пауза → включить ANC → пауза → прозрачный режим → пауза → выключить ANC.
4. Повторите цикл 2–3 раза (кадры должны повторяться — это поможет не спутать их со служебными).

### Шаг 3. Достаньте btsnoop_hci.log

Без root проще всего так:

- Настройки → Для разработчиков → **«Снять отчёт об ошибке»** (Bug report) →
  дождитесь готовности → в полученном архиве ищите
  `FS/data/misc/bluetooth/logs/btsnoop_hci.log`.

Либо через ПК:

```bash
adb bugreport report.zip
# в report.zip: FS/data/misc/bluetooth/logs/btsnoop_hci.log
```

### Шаг 4. Найдите ANC-кадры в Wireshark

1. Откройте `btsnoop_hci.log` в **Wireshark** (бесплатно, wireshark.org).
2. Фильтр по записям ATT (именно через ATT идут команды):

   ```
   btatt.opcode.method == 0x52 || btatt.opcode.method == 0x12
   ```
   (0x52 — Write Command, 0x12 — Write Request: то, чем приложения пишут в наушники).

3. Ищите записи, чей payload начинается с байтов **`fe dc ba`** — это синхронизация кадров
   RCSP (протокол вендорских команд Jieli). Формат кадра:

   ```
   FE DC BA | len (2 Б, little-endian) | cmd (2 Б, LE) | payload | CRC16 (2 Б, LE)
   ```

4. Сопоставьте время кадра с моментами переключения ANC (вы делали паузы —
   кадры «включить ANC», «выключить», «прозрачный» будут заметно разнесены по времени
   и, как правило, отличаются в 1–2 байтах payload).
5. Определите **handle** (столбец Destination/Source Handle в ATT-записи) —
   это адрес характеристики, куда пишет hoco.music.

### Шаг 5. Перенесите кадры в приложение

1. В приложении EQ27 ANC → вкладка **«Лаборатория» → «Дамп GATT»** —
   найдите характеристику с тем же UUID, куда писал hoco.music (обычно внутри сервиса
   `0xAE00`, характеристика `0xAE01`; на новых прошивках встречается `0xAE80/0xAE81`).
2. Если UUID совпал с автовыбором — ничего менять не надо. Если нет — выберите
   нужную характеристику в **«Параметрах отправки»**.
3. Вкладка **«Шумодав»** → «Изменить кадры режимов» → вставьте три кадра
   (выкл / ANC / прозрачный), скопированные из Wireshark **целиком, вместе с FE DC BA и CRC**.
4. Готово. Кнопки режимов теперь шлют команды наушникам.

> **Кадры можно вставлять «как есть»** — приложение отправляет байты без изменений,
> пересчёт CRC не требуется. Пересборка кадров (конструктор) нужна только если вы
> захотите писать свои команды с нуля.

### Если кадры не «FE DC BA…»

Редко, но бывает, что прошивка говорит не на классическом RCSP. Тогда:

- снимите **все** Write-записи вокруг момента переключения ANC (фильтр из шага 4)
  и найдите 1–3 кадра, которые появляются **строго** в моменты переключения и повторяются;
- вставьте их в приложение тем же способом — слать можно любые сырые байты;
- обратите внимание, не пишется ли сначала кадр-«переключатель контекста» — тогда
  сохраните его как «Моя команда» и жмите перед ANC-кадром.

## Лаборатория протокола

Вкладка **«Лаборатория»** — инструмент reverse engineering:

| Секция | Что делает |
|---|---|
| **Отправить HEX** | шлёт любые байты в выбранную TX-характеристику, длинные кадры автоматически режутся на куски по MTU |
| **Конструктор кадра RCSP** | собирает кадр из команды и payload: `FE DC BA + len + cmd + payload + CRC` |
| **Решатель CRC** | вставьте захваченный кадр — приложение подберёт, какой вариант CRC16 (CCITT-FALSE, XMODEM, MODBUS, ARC; по data или по len+data) совпадает с прошивкой |
| **Мои команды** | сохранённые кнопки для любых кадров (имя + HEX) |
| **Параметры отправки** | выбор TX/RX-характеристик вручную, WRITE_NO_RESPONSE, размер куска |
| **Дамп GATT** | полная таблица сервисов/характеристик с флагами свойств |
| **Журнал** | все события: скан, подключение, TX/RX в HEX, ошибки; можно «Поделиться» текстом |

## О протоколе

Что достоверно известно на момент сборки проекта:

- Чип: **JieLi AC7003D4** (серия AC700N), Bluetooth 5.4.
- Приложение hoco.music построено на стеке **RCSP** (Remote Control Serial Protocol) —
  это подтверждается кадрами `FE DC BA …` в трафике других наушников на Jieli и
  публичными исходниками SDK Jieli (fw-AC63_BT_SDK и родственные).
- Типичные BLE-сервисы Jieli:
  - `0000ae00-…` / `0000ae01-…` (write) / `0000ae02-…` (notify) — канал управления/данных;
  - `0000ae80-…` — встречается на новых прошивках (RCSP adv/OTA);
  - кадры длиннее MTU-3 режутся на части.
- Приложение **автоматически** ищет эти сервисы и выбирает TX/RX, так что в большинстве
  случаев ручная настройка не понадобится.

Точный номер ANC-команды (поле `cmd`) **зависит от прошивки** и в открытых источниках
для EQ27 не опубликован — поэтому в проекте заложен путь «перехват и повтор», который
гарантированно приводит к рабочему кадру за 10–15 минут.

Полезные материалы сообщества:

- Документация по чипам/протоколам Jieli: https://kagaimiq.github.io/jielie/
- Открытый SDK Jieli (протокол RCSP в коде): https://github.com/Jieli-Tech/fw-AC63_BT_SDK
- Wireshark: https://www.wireshark.org/

## Траблшутинг

| Симптом | Причина и решение |
|---|---|
| «Попытка N не удалась», статус 133 | Классика дешёвых BLE-чипов. Уберите наушники из кейса, закройте hoco.music, выключите/включите Bluetooth, повторите. Приложение само делает 4 попытки. |
| Устройство найдено, но не подключается | Наушники уже заняты другим приложением (hoco.music, транслятор). Закройте его. Иногда помогает забыть наушники в настройках Bluetooth и сопрячь заново. |
| Кадр уходит, наушники молчат | Не та TX-характеристика (проверьте handle из Wireshark против «Дампа GATT») либо нужен предварительный кадр-переключатель контекста. |
| Нет входящих пакетов (RX) | Уведомления не включились. В «Параметрах отправки» выберите RX-характеристику вручную (та, где NOTIFY в дампе). |
| Записи не проходят | Попробуйте переключить WRITE_NO_RESPONSE (у некоторых характеристик только WRITE с подтверждением). |
| Кадр больше ~20 Б не доходит | Проверьте MTU в баннере; уменьшите «Кусок» до 20 в «Параметрах отправки». |
| «Нет разрешения BLUETOOTH_CONNECT» | Выдайте разрешения: Настройки → Приложения → EQ27 ANC → Разрешения → «Устройства поблизости». |
| Обновление скачалось, но не устанавливается | Подпись не совпадает (см. «Обновление из приложения») либо не выдано разрешение «Установка неизвестных приложений» — выдайте и нажмите «Установить» ещё раз. |
| «Ошибка проверки: …» в карточке обновления | Нет интернета или GitHub API недоступен. Проверьте соединение; релиз должен существовать (см. Releases репозитория). |

## Идеи развития

- Foreground-сервис + **Tile в шторке** для мгновенного переключения ANC;
- автопроверка обновлений при запуске (сейчас — только кнопкой);
- автопереключение ANC при подключении наушников (приёмник `ACTION_ACL_CONNECTED`);
- эквалайзер и батарея — кадры ловятся тем же способом, что и ANC;
- экспорт/импорт профилей кадров в JSON;
- поддержка нескольких моделей наушников (вся логика завязана на кадры, не на модель).

## Дисклеймер

Проект — исследовательский. Команды ANC/EQ — обычные вендорские команды уровня
«настроек», они не перепрошивают наушники и безопасны. Тем не менее **не отправляйте
наугад кадры OTA/прошивки** (загрузчик, стирание памяти) — это единственный способ
реально навредить устройству. Коды протокола неофициальные, поведение может отличаться
между прошивками.
